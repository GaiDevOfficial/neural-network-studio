# Licensing model

## Short version

| Material | License |
|---|---|
| Source code, tests, build scripts | **AGPL-3.0-or-later** |
| Documentation and diagrams | AGPL-3.0-or-later |
| Node Studio name, logo and visual identity | Trademarks, all rights reserved |
| Commercial/proprietary use without AGPL obligations | Separate written commercial license |

## Why AGPL?

The AGPL is an OSI-approved open-source license with strong copyleft. If someone modifies Node Studio and
distributes it, they must provide the corresponding source under the AGPL. If they run a modified version
as a network service, the AGPL's network clause requires them to offer the corresponding source to the
users of that service.

This is the strongest protection available while keeping the project genuinely open source. It prevents a
company from taking the code, making a proprietary derivative and hiding the changes. It does **not**
prevent a company from using the unmodified project internally, and it does **not** prevent an independent
team from reimplementing the same idea from scratch.

## What a license can and cannot protect

Copyright protects the expression of the software: the source code, documentation, tests, artwork and the
specific way the project is built. It does not protect abstract ideas, algorithms, workflows, game rules or
the general concept of a visual neural-network builder. Those may be covered by patents, trademarks or
trade secrets, but not by a copyright license.

No open-source license can guarantee that a large company will not study the project, learn from it or
build a competing product. The practical protections are:

1. **AGPL copyleft** - proprietary derivatives and modified hosted services must share their source.
2. **Trademark policy** - forks cannot present themselves as official Node Studio.
3. **Commercial licensing** - organizations that need proprietary terms must sign a separate agreement.
4. **Clear copyright notices** - every copy carries the origin and license terms.

If your priority is to forbid **all** commercial use, including internal use by a company, then the project
should use a source-available non-commercial license such as PolyForm Noncommercial 1.0.0 instead of an
OSI open-source license. That is a different trade-off: the source stays public, but the project is no
longer "open source" under the OSI definition. The current choice is AGPL to keep the project open source
while imposing the strongest copyleft available.

## Contributions

By contributing, you agree that your contribution is licensed under AGPL-3.0-or-later and that the
maintainer may also offer it under a commercial license. Do not contribute code you cannot license on
those terms.
